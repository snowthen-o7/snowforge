## New Issues the Progress Exposed

These are net-new findings, visible only because earlier blockers are cleared:

1. **`Color/Size missing for 301 apparel items (0.6%)`** — the variant attribute mapping (T8 fix) works for most products but misses some. Likely cause: Shopify products with non-standard option names (`Colour` vs `Color`, or product-specific names like `Flavor`, `Style`). The mapping probably looks only for exact `Color`/`Size` and needs a case-insensitive + alias list.

2. **`Price consistency outliers: 20 prices >10x or <0.1x median`** — worth eyeballing. Could be legitimate high-priced items (snowboards vs accessories) or could be transformation artifacts.

3. **`identifier_exists=no with MPN populated (100% of rows)`** — T10 follow-up. The MPN mapping worked but identifier_exists wasn't updated to reflect it.

4. **GPC granularity shallow for 304 products** — only slightly up from baseline (was 4, now 304). This is the AI categorization partial coverage: the 2,824 products it did categorize include some shallow ones like "Gift Cards" (1 tier). Fine to ignore for now, minor polish.

5. **Product type <3 tiers for 100%** — Shopify's `product_type` is typically a single string like `snowboard` or `giftcard`, not a hierarchical path. If SnowPipe wants this to pass the audit, it would need to enrich product_type from the category taxonomy or Shopify collections. Low priority.

## Next Iteration Brief (condensed)

Hand this to the SnowPipe agent for iteration 2:

> **Priority 1: Fix remaining Critical FAILs blocking GMC.**
>
> 1. **Title empty for 414 rows (T4 unchanged).** The current transform produces `title=""` for products where Shopify's variant title is `"Default Title"` (the single-variant placeholder). The fix is: always use `product.title` as the base. Only append variant info when `product.variants.length > 1 AND variant.title !== 'Default Title'`.
> 2. **Image link empty for 99.95% (S1 unchanged).** The source sync captures `variant.image.url` but leaves it blank when the variant has no variant-specific image. Must fall back to `product.featuredImage.url` or `product.images.nodes[0].url`.
>
> **Priority 2: Availability logic (T3 unchanged).**
>
> Currently 99.96% of products report `out_of_stock`. The raw Shopify data shows 86% have product status ACTIVE. The transform should check: if product.status != 'ACTIVE' → out_of_stock; else if variant.inventoryPolicy == 'CONTINUE' → in_stock; else if variant.availableForSale or variant.inventoryQuantity > 0 → in_stock; else out_of_stock.
>
> **Priority 3: Variant location duplication (T7 unchanged).**
>
> The feed has 51,192 rows but should probably have ~12,798 (4x smaller). Investigate whether the source sync is emitting one row per (variant, inventory location) instead of one row per variant. Check `NextVend`'s location count in Shopify. If there are 4 locations, that explains the 4x multiplier exactly.
>
> **Priority 4: GPC at scale (T6 partial).**
>
> AI categorization covered ~5.5% (2,824 of 51,192). Either the batch didn't complete, results weren't persisted, or the awaiting-approval queue is blocking output. Resolve the coverage gap.
>
> **Priority 5: identifier_exists follow-up (T10).**
>
> Now that MPN is populated, `identifier_exists` should compute as `(gtin || mpn) ? 'yes' : 'no'` per row, or the attribute should be dropped entirely and Google will infer.
>
> **Priority 6: Variant attribute edge cases (new).**
>
> 301 apparel products (0.6%) still lack color or size. Probably caused by non-`Color`/`Size` option names. Add a case-insensitive alias map: `colour → color`, etc.
>
> Deferred to iteration 3: S3 (shipping_weight), T5 follow-up (description fallback source), product_type tiers.
